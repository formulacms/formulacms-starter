# Upgrade from formulacms 0.1.1 to 0.2.0

This file explains formulacms 0.2.0 for a site made from 0.1.0 or 0.1.1. You
can read it yourself, or give it to a coding agent.

**Kind of upgrade: unsupported transition (fresh install only).** Sign-in
moves from Better Auth to Convex Auth, with a username and a password. A site
made from 0.1.0 or 0.1.1 cannot keep its accounts: the two sign-in systems
keep accounts in different tables, and this release has no tool that moves
them. Do not merge 0.2.0 into a 0.1.x site, and do not `git pull` it either.

The release check in your 0.1.x site says the same. Run it in your site's
folder:

```bash
node --import tsx scripts/check-release-transition.ts --source-tag v0.1.1 --target-tag v0.2.0
```

It prints this line and stops with an error:

```text
Unsupported transition: v0.1.1 -> v0.2.0.
```

A site made from 0.1.0 gets the same answer with `--source-tag v0.1.0`.

## Read this file from a 0.1.x site

Your 0.1.x site does not contain this file. Run these commands in your site's
folder to read it from the 0.2.0 release:

```bash
git remote add starter https://github.com/formulacms/formulacms-starter.git
git remote set-url --push starter DISABLED
git fetch starter --tags
git show v0.2.0:upgrades/v0.1.1-to-v0.2.0.md
```

If git says that the remote `starter` already exists, go on to the next
command. The second command stops any push to the starter by mistake.

## Coding agents: stop and ask the person first

Stop and ask the person before you change anything when the site was made
from 0.1.0 or 0.1.1. Merging 0.2.0 into it removes the old sign-in, and the
existing accounts stop working. Show the person this file and the section
"What to do with a 0.1.x site".

## What changes in sign-in

- **Username and password.** The owner signs in with a username and a
  password (`convex/auth.ts`, `app/(core)/(auth)/sign-in/page.tsx`).
  Passwords have 10 to 100 characters.
- **Setup.** The account step of `/setup` asks for your name, a username, a
  password (twice), an optional notification email and the owner setup code
  (`components/setup/setup-wizard.tsx`).
- **Notification email.** This address only receives contact messages and
  the test email. It is never used to sign in. You can change it in
  Settings > Email (`components/admin/email-settings.tsx`).
- **Change password.** The owner changes the password in Settings > Account
  (`components/admin/settings/change-password.tsx`).
- **Sessions.** A session lasts at most 30 days, and it ends after 7 days
  without use. Sign-out ends a session at once (`convex/auth.ts`).
- **Sign-in limit.** Every password check counts, right or wrong. After 5
  checks, an account accepts one check a minute (Convex Auth's own limit).
  Owner recovery (below) still works while an account is locked.
- **Environment.** Sign-in needs no auth secret and no auth URL. Convex Auth
  signs its own tokens in the Convex backend. `pnpm dev` now writes two
  secrets, `CONTACT_IP_PROOF_SECRET` and `REVALIDATE_SECRET`
  (`scripts/lib/local-setup.ts`). A local address in `NEXT_PUBLIC_SITE_URL`
  also sets the address `pnpm dev` binds (`scripts/lib/dev-server-origin.ts`).

## What 0.2.0 removes

- Sign-in with an email address.
- Password reset by email, and the `/forgot-password` and `/reset-password`
  pages.
- Sign-in with Google, and its settings.
- Invitation email delivery. A 0.1.x site had no screen to send invitations.
- The password-reset script `admin:reset-password` in `package.json`.
- The environment values `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`, in
  `.env.local` and in Convex.
- Owner replacement with a new owner setup code. Setup now accepts the code
  only while the site has no owner (`convex/cms/owner.ts`).

## How owner recovery works now

When the owner forgets the password, or wrong guesses lock the account, run
this command in the site's folder:

```bash
pnpm owner:recover
```

It prints a one-time link (`scripts/owner-recover.ts`). The link works once
and expires after 15 minutes. A new link replaces the previous one. Convex
stores only a hash of the link (`convex/cms/recovery.ts`). Add `--prod` for
the production backend.

Open the link and choose a new username and password. Ownership moves to the
new account at once. The old account is disabled, its sessions end, and
sign-in refuses it. "Owner recovery" in `docs/starter/operations.md` has the
details.

## What to do with a 0.1.x site

Keep the 0.1.x site as it is. To use 0.2.0, create a new site from the 0.2.0
starter and complete `/setup` with a new owner account, as the README
Quickstart says. The new site starts with no content. This release has no
tool that moves pages, media or settings from a 0.1.x site.

## If you already pulled or merged 0.2.0

Do not start the site with 0.2.0 code in your 0.1.x folder. Do not run
`pnpm dev`, `pnpm exec convex dev` or `pnpm exec convex deploy`.

Git can refuse the pull. It then ends with
`fatal: Need to specify how to reconcile divergent branches.` or
`fatal: Not possible to fast-forward, aborting.` Your files and commits did
not change. You have nothing to undo.

If the pull or merge stopped before it finished, for example with
`CONFLICT`, cancel it:

```bash
git merge --abort
```

If git prints nothing, your site is back as it was. Go to the check below.
If git answers `fatal: There is no merge to abort (MERGE_HEAD missing).`,
cancel a stopped rebase instead:

```bash
git rebase --abort
```

If git prints nothing, your site is back as it was. Go to the check below.
If git answers `fatal: no rebase in progress`, the pull or merge is already
committed. Go on with the next step.

If the pull or merge is already committed, find the commit from before it:

```bash
git reflog
```

The newest line comes first. Each line starts with a commit, then
`HEAD@{n}:`, then what git did. Find the newest line where that text starts
with `pull`, `merge` or `commit (merge)`. If that line says `(finish)`, go
down to the line that says `(start)`. The line just below starts with the
commit from before the pull. For example, after `git pull --rebase`:

```text
97d68bf HEAD@{0}: pull --rebase (finish): returning to refs/heads/main
97d68bf HEAD@{1}: pull --rebase (pick): my note 1
70425c3 HEAD@{2}: pull --rebase (start): checkout 70425c3bf11adb0923eb3ed47782929423cb3e12
80d3819 HEAD@{3}: commit: my note 1
```

Here the commit from before the pull is `80d3819`. Your commits differ.

`git reset --hard` also deletes changes that you have not committed in files
that git tracks. New files that git does not track stay in the folder. Copy
your changed files to another folder first. Do not commit them: the reset
removes that commit from your branch too. Then go back to the commit from
before the pull:

```bash
git reset --hard <the commit before the pull>
```

Check that the site is back on 0.1.x:

```bash
grep '"version"' package.json
```

It prints `"version": "0.1.0",` or `"version": "0.1.1",`.

If you already started the site with 0.2.0 code, your Convex backend may
have received it. Going back to 0.1.x after that is not tested.

## Other changes in 0.2.0

- `pnpm lint` now also runs the Convex lint rules on `convex/`
  (`eslint.config.mjs`). Your own Convex code can fail these rules.
- 11 duplicate database indexes are removed from `convex/schema.ts`.
- `pnpm dev` now serves its development files, such as hot reload, at
  `127.0.0.1` and `[::1]` too, not only at `localhost` (`next.config.ts`).
- `pnpm slices:author` now runs in a site that you cloned with git. Sign it
  in once from your site's folder. The address is your local Convex backend:

  ```bash
  pnpm slices:author login --app-root . --backend-url http://127.0.0.1:3210
  ```

  `docs/starter/content-model-authoring.md` explains the sign-in.
- The recovery page `/recover` shows the expired message at once for a link
  that was already used.

## Roll back

A new 0.2.0 site does not change your 0.1.x site. To go back, keep using the
0.1.x site and its backend.
